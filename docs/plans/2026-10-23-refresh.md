# Style Scratcher — Liquid Studio refresh

## Intent and scope

Upgrade the existing Manifest V3 browser extension, preserving its name, Apache-2.0 license, crimson identity, and inspect/edit tools. Deliver a coherent liquid-glass experience, a real introductory website, dependable runtime behavior, and an understandable open-source repository. The user's instruction delegates design and implementation choices and requires shallow checkout, `chatgpt/` branches, small commits, and a push after every commit.

## Design

**Philosophy:** understand the web, make deliberate changes, keep the user in control. The inspector starts on demand; the page remains usable until explicitly inspected. Explain limitations without claiming impossible fidelity or guaranteed safety.

**Visual system:** retain Studio Crimson `#E11D48`, add Ink `#17151C`, warm pearl surfaces, translucent borders, restrained blur, clear type hierarchy, visible keyboard focus, reduced-motion behavior, and a solid fallback. Evolve the existing selection-box/crosshair mark into a reproducible vector identity. Chrome controls remain legible on arbitrary host pages.

**Architecture:** retain the installable manifest at repository root and the stable `content/`, `popup/`, `background/`, `icons/` paths. Put the website in `website/`, repeatable tooling in `scripts/`, regression tests in `test/`, and maintainer/brand/architecture/verification material in `docs/`. No framework or production dependency is needed.

**Behavior:** derive injection order from the manifest, use truthful popup loading/error states, make runtime initialization idempotent, stop unnecessary work while inactive, bound heavy scans, and fix confirmed defects with regression coverage.

## Review focus

1. A page opened before extension installation/reload must activate once without duplicate declarations or listeners.
2. Restricted pages, closed tabs, failed injection, denied clipboard access, and unavailable browser APIs must produce truthful feedback.
3. Deactivation must stop overlay work and restore auxiliary interaction modes.
4. Large DOMs, long identifiers, hostile markup and missing elements must not hang or corrupt the studio.
5. Narrow windows, keyboard navigation, reduced motion, and unsupported blur must remain usable.
